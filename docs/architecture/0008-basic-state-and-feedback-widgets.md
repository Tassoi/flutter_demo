# ADR 0008：基础状态与反馈组件

- 状态：Accepted
- 决策日期：2026-08-09
- 适用范围：第一阶段加载、空、错误状态、确认弹窗与短时消息反馈，以及第二阶段手机布局适配

## 背景与范围

不同 Feature 都需要表达加载、无内容、失败、确认和短时操作结果。如果各页面自行拼装，容易产生不一致的点击目标、窄屏溢出、缺失语义播报以及把底层异常直接展示给用户的问题。

本决策在 `lib/shared/widgets/` 提供五类无业务语义的 Material 组件。它们只负责布局、视觉语义、
参数校验和操作转发，不读取网络、存储、日志、路由状态或业务模型，也不实现状态管理、请求
重试、并发去重或国际化。第二阶段 Task 4 让组件消费项目 `du/dsp` 和主题，不直接导入底层
适配插件；文案和异步生命周期仍由调用方拥有。

共享组件需要与应用主题使用同一套间距和圆角。布局 token 因此从 `app/theme` 移到 `shared/design`；`app/` 和 `shared/widgets` 都依赖该中立边界，`shared/` 不反向依赖 composition root。

## 状态视图

`AppLoadingState` 在稳定的 64×64 参考稿视觉槽内展示 32×32 进度指示器，两种尺寸都在运行时
通过 `du` 解析。`AppEmptyState` 提供标题、可选说明、装饰和调用方操作。`AppErrorState`
提供安全标题、说明及成对出现的重试标签和回调。装饰图形从语义树排除，状态含义必须由文字表达；加载和
状态变化使用 live-region 语义，让辅助技术能够感知更新。

三种状态共享以下约束：

1. 必填文案不得为空白，错误文案不得直接使用异常 `toString()`、响应正文、路径、Token 或个人数据。
2. 组件不发起请求，也不控制加载切换、重试次数、退避、取消或重复点击；调用方状态管理单元负责这些行为。
3. 内容和操作宽度分别使用 480/320 参考稿上限；交互目标取 `du(48)` 与原始 48 逻辑像素的较大值。
4. 有界高度下内容在空间充足时居中；短屏、横屏或系统文字放大造成空间不足时允许纵向滚动，不缩小文字或伪造 MediaQuery 数据。单个操作高于极端短屏时，其上下边缘仍必须可滚动到达且完整标签不能被裁切。
5. 内部 `padding` 省略时使用 `du(AppSpacing.lg)`；调用方自定义值已经是最终逻辑 Insets，必须有限、非负且不得混入页面 SafeArea 或键盘值。

## 确认弹窗

`showAppConfirmationDialog` 使用根 Navigator 展示不可通过遮罩误触关闭的 Material 对话框。取消返回 `false`，确认返回 `true`，系统返回键或其他未提供结果的关闭路径统一折叠为 `false`。弹窗在路由退出动画前锁定第一次明确决策，并在系统返回已经开始关闭路由后忽略迟到的按钮事件，连续操作不会二次弹出下方路由。`isDestructive` 只切换错误色和警告/删除图标，不执行删除或其他副作用。

标题、正文和两个操作标签都必须是非空安全文案。弹窗启用安全区和滚动；inset、图标、间距
和按钮外观使用项目设计单位，两个操作放在同一滚动内容内，并使用可换行的全宽按钮，避免
Flutter 3.29 中独立 actions 区在短屏、大文字或长标签下超出可视区域。调用方必须在事件回调
或帧结束后调用，不能在 Widget `build` 期间推入路由。

## 短时消息反馈

`showAppMessageFeedback` 通过最近的 `ScaffoldMessenger` 展示浮动 SnackBar，并返回框架控制器供调用方观察关闭原因或主动关闭。`AppMessageKind` 只把 information、success、warning、error 映射到现有 `ColorScheme` 角色和熟悉图标；它不是日志级别或业务错误分类。

默认 `replaceCurrent: true` 会先清除当前及排队中的旧消息，确保快速状态变化最终只显示最新反馈。确实需要按顺序展示时，调用方可以显式设为 `false`。没有操作时显示关闭图标；存在操作时，标签和回调必须同时提供，包装器最多转发一次回调，并以 action 原因关闭当前消息。Flutter 3.29 的原生 `SnackBarAction` 在大文字下会按未缩放标签宽度参与布局，因此这里使用高度至少 48、宽度最多 320 且允许换行的自有动作区域。

消息时长必须大于零，文案同样不得携带内部诊断信息或敏感数据。消息正文与操作位于有高度
上限的内部滚动容器；上限同时读取局部 MediaQuery 和所属 FlutterView 的原始 padding/
viewInsets。即使 API 从已经消费 SafeArea 的子树调用，也不会高估 Scaffold 可用于浮动消息的
高度。该 API 不持久化、不记录、不重试消息，也不会修改业务状态；没有
`ScaffoldMessenger` 的上下文会由 Flutter 明确报错，而不是静默丢弃反馈。

## 测试与验证

Widget 测试覆盖状态内容与回调、空白/非法留白和参数配对校验、加载尺寸、live-region 和装饰
语义、确认三种关闭结果、第一次决策锁定、系统返回后的迟到操作、48 像素操作目标、破坏性
颜色、反馈种类映射、最新消息替换、回调产生后续反馈、关闭图标及动作只转发一次。三类组件
在六档手机视口分别执行正常和 200% 系统文字场景，断言安全边界、完整标签、滚动可达性、
按钮动作和语义；首页与详情 Golden 提供同一主题/组件体系的参考像素回归。

常规验证命令：

```bash
dart format --output=none --set-exit-if-changed .
flutter analyze
flutter test
flutter build apk --debug --flavor dev \
  --dart-define-from-file=config/dev.example.json
```

## 已知限制、迁移与回滚

当前没有为每一种状态、弹窗和反馈分别维护截图 Golden；关键页面 Golden 与矩形/语义矩阵
共同覆盖现有默认流程。仍缺少 iOS 实机 VoiceOver、Android 实机 TalkBack 和所有语言长文案
验证。组件不替代业务页面骨架屏、表单级错误、持久通知或启动失败 fallback；后者必须保持
不依赖共享资源和初始化结果的最小实现。加入国际化后，调用方应传入已经本地化的文案，不在
这些组件内部查找翻译。

更改公开构造参数、反馈默认排队策略、确认返回语义、语义树或尺寸上限属于跨 Feature 行为变更，必须附迁移说明并重新运行窄屏、大文字和无障碍测试。Flutter 升级后应重新验证 AlertDialog 与 SnackBar 的布局行为；框架原生组件能够满足同一契约时，可以在不改变公开 API 的前提下简化内部布局。

仅回滚 Task 9 时，移除 `lib/shared/widgets/`、对应 Widget 测试和本 ADR，将布局 token 及其导入从 `shared/design` 恢复到 `app/theme`，并同步恢复 ADR 0007 与目录 README。不得回退 Task 1-8、覆盖用户的 `AGENTS.md` 或修改 Goal 原文。
